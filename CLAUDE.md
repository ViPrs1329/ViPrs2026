# RobotPy FRC Repository Guidelines

## CRITICAL: Avoid Hallucinated / Outdated Syntax
- Always check our local code and imports before writing RobotPy code.
- We use the **Command-Based Framework (v2)**. Do NOT use legacy `commandbased` or `TimedRobot` patterns unless specified.
- Never invent WPILib method names. If unsure of an API method, ask or refer to the local type stubs / Python environment.

## Environment & Commands
- **Python Version:** 3.11+
- **Python path:** `.venv/bin/python`
- **Run Simulator:** `python -m robotpy sim`
- **Run Tests:** `pytest` / `python -m pytest`
- **Formatter/Linter:** `ruff check .` / `black .`

## Code Structure & Conventions
- `robot.py`: Main entry point (instantiates `RobotContainer`).
- `robotcontainer.py`: Binds controller inputs, configures autonomous routines, and instantiates subsystems.
- `subsystems/`: One file per subsystem (e.g., `arm.py`). Must subclass `commands2.Subsystem`.
- `commands/`: Complex multi-subsystem commands. Simple subsystem actions should use inline `commands2.cmd` factories (e.g., `subsystem.runOnce(...)` or `subsystem.run(...)`).
- `constants.py`: Store all CAN IDs, DIO ports, PID gains, and physical dimensions.

## Key Hardware & Vendor Libraries
- **Drivetrain:** [e.g., Swerve / Phoenix 6 / REV MAXSwerve]
- **Motor Controllers:** [e.g., `phoenix6`, `rev`, or `ctre`]
- **Sensors:** [e.g., `navx`, `photonlibpy`, `limelightlib`]

## Mandatory Coding Patterns
1. **Typing:** Use strict type hints on all method signatures (`def execute(self) -> None:`).
2. **Command Requirements:** Always declare `self.addRequirements(self.subsystem)` in custom Command `__init__` methods.
3. **Constants:** Never hardcode CAN IDs or ports outside of `constants.py`.
4. **Simulation:** Keep hardware calls separated from logic so `simulationPeriodic()` can run smoothly without physical devices attached.
5. **Variable Naming:** Write using camelCase, not snake_case. This keeps the code consistent. The only exception is src/subsystems/krakenDriveSubsystem.py and src/generated/tuner_constants.py, which contain code generated by Phoenix Tuner X.
